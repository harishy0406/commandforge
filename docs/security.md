# CommandForge Security Model & Defense in Depth

CommandForge treats natural language-derived shell execution as an untrusted, high-risk activity. No single safeguard is considered sufficient. Security is achieved through multiple non-overlapping defensive barriers:

```
+-------------------------------------------------------------+
| Layer 1: Prompt & Context Sanitization                      |
| - Boundary injection filtering                              |
| - Truncation of untrusted user input                        |
+-------------------------------------------------------------+
                              v
+-------------------------------------------------------------+
| Layer 2: Deterministic AST & Token Static Policy            |
| - Block destructive patterns (e.g., fork bombs, raw devices)|
| - Block access to /proc/kcore, /dev/sd*, raw sockets        |
| - Detect chained subshells, pipe tricks, and obfuscation    |
+-------------------------------------------------------------+
                              v
+-------------------------------------------------------------+
| Layer 3: Mandatory Human-in-the-Loop Approval               |
| - Commands NEVER execute automatically upon generation      |
| - High-risk commands require dual-step confirmation modal    |
| - Clear plain-language explanation of side effects          |
+-------------------------------------------------------------+
                              v
+-------------------------------------------------------------+
| Layer 4: Sandboxed Container Isolation (Docker)             |
| - Non-root execution (UID 10001, GID 10001)                 |
| - Read-only root filesystem with ephemeral tmpfs scratch    |
| - Drop all Linux capabilities (--cap-drop=ALL)              |
| - Network isolation disabled by default (--network none)    |
| - Memory limits (e.g. 256MB) & CPU quotas (e.g. 0.5 CPU)    |
| - PIDs limit (e.g. 64) to prevent fork-bomb resource leaks  |
+-------------------------------------------------------------+
                              v
+-------------------------------------------------------------+
| Layer 5: Timeouts & Output Buffer Guards                    |
| - Wall-clock process timeouts with SIGKILL termination      |
| - 64 KB output caps preventing denial of service in logging |
+-------------------------------------------------------------+
                              v
+-------------------------------------------------------------+
| Layer 6: Secrets & Audit Logging                            |
| - Zero API credentials in responses or client state         |
| - Redaction of tokens and environment keys from audit DB    |
+-------------------------------------------------------------+
```

## Security Guarantees and Non-Goals
1. **Never on Host**: Commands generated by CommandForge are never dispatched directly to the host OS.
2. **Deterministic Fallback**: If Docker is unavailable or misconfigured, execution fails safely rather than downgrading to un-isolated host execution.
3. **No Secret Leakage**: The backend validates that incoming commands do not query `/etc/shadow`, environment variables containing keys, or cloud credential metadata endpoints (169.254.169.254).
